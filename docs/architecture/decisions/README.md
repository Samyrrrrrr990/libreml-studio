# Architecture decision records

ADRs record decisions that are expensive to reverse or affect persisted/public behavior. Status values are `proposed`, `accepted`, `superseded`, or `rejected`.

- [ADR-0001: Monorepo boundaries](0001-monorepo-boundaries.md)
- [ADR-0002: Loopback-first packaging](0002-loopback-first-packaging.md)
- [ADR-0003: Versioned JSON project format](0003-versioned-json-project-format.md)
- [ADR-0004: Python analytical executor](0004-python-analytical-executor.md)
- [ADR-0005: Deterministic explanations](0005-deterministic-explanations.md)
- [ADR-0006: AGPL community edition and commercial alternative](0006-dual-licensing.md)

New ADRs should state context, decision, alternatives, consequences, security/privacy/methodology effects, and follow-up conditions. Never rewrite an accepted decision to hide history; supersede it.
